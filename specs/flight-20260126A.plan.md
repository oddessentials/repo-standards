## Executive Summary

This plan details the technical approach to implement Flight 20260126A, transforming repo-standards from a standards distribution library into an orchestration platform. The implementation follows a phased approach, building foundational schemas first, then commands, then integration systems.

## Implementation Phases

### Phase 1: Schema Definitions

**Goal:** Define all 7 required schemas with full TypeScript types.

**Priority:** Critical — all other phases depend on these schemas.

#### 1.1 Finding Schema (`src/schemas/finding.ts`)

```typescript
export type RemediationClass = "mechanical" | "ai" | "human";
export type RiskLevel = "low" | "medium" | "high" | "critical";
export type Severity = "error" | "warn" | "info";

export interface Finding {
  finding_id: string; // Unique identifier (UUID v4)
  rule_id: string; // Reference to standards rule
  severity: Severity;
  title: string;
  description: string;
  file_path?: string; // Affected file (if applicable)
  line_number?: number; // Affected line (if applicable)

  // Routing metadata (for conductor)
  remediation_class: RemediationClass;
  remediation_hint: string; // Actionable remediation guidance
  risk: RiskLevel;
  estimated_scope: "single-file" | "multi-file" | "cross-cutting";
  confidence: number; // 0-1, confidence in classification

  // Timestamps
  detected_at: string; // ISO 8601 UTC
}
```

### Phase 2: Core Utilities

**Goal:** Build foundational utilities for commands.

#### 2.1 Input Hash Computation (`src/core/input-hash.ts`)

**Purpose:** Deterministic hash of all verification inputs.

**Algorithm:**

1. Collect all input files (sorted by path)
2. Hash each file's content
3. Include standards version and config
4. Sort and concatenate all hashes
5. Compute final SHA-256

**Key Constraint:** No network access, no external state.

#### 2.2 Config Loader (`src/core/config-loader.ts`)

**Purpose:** Load and parse `.odd/standards.toml`.

**Responsibilities:**

- Locate `.odd/standards.toml` in repository
- Parse TOML configuration
- Validate against expected schema
- Return typed configuration object

**Dependencies:** Consider `@iarna/toml` or similar for TOML parsing.

#### 2.3 File Scanner (`src/core/file-scanner.ts`)

**Purpose:** Scan repository files for verification.

**Responsibilities:**

- Walk directory tree (respecting `.gitignore`)
- Collect file metadata
- Build `InputManifest`
- Compute file hashes

**Performance:** Must handle 10,000 files in <60 seconds.

#### 2.4 Rule Engine (`src/core/rule-engine.ts`)

**Purpose:** Evaluate standards rules against repository state.

**Responsibilities:**

- Load standards for declared stack
- Evaluate each checklist item
- Check required files, scripts, configurations
- Produce `Finding` objects for violations

### Phase 3: Command Implementations

**Goal:** Implement the 4 required CLI commands.

#### 3.1 Verify Command (`src/commands/verify.ts`)

**Usage:**

```bash
repo-standards verify <path>
repo-standards verify .              # Current directory
repo-standards verify --json         # JSON output (default)
repo-standards verify --summary      # Summary only
```

**Algorithm:**

1. Load `.odd/standards.toml` from target path
2. Determine stack and standards version
3. Scan repository files (build `InputManifest`)
4. Compute `input_hash`
5. Load standards rules for stack
6. Evaluate each rule against repository
7. Classify findings (severity, remediation_class, risk)
8. Build and return `VerifyResult`

**Outputs:**

- Exit code 0: Compliant (`is_compliant: true`)
- Exit code 1: Non-compliant (findings exist)
- Exit code 2: Error (invalid config, etc.)

**Invariant Enforcement:**

- No network access during execution
- Deterministic: same inputs = same outputs
- `input_hash` stable across runs

#### 3.2 Apply Command (`src/commands/apply.ts`)

**Usage:**

```bash
repo-standards apply <path>
repo-standards apply . --dry-run     # Show what would change
repo-standards apply . --force       # Overwrite existing files
```

**Algorithm:**

1. Load `.odd/standards.toml` from target path
2. Determine stack and standards version
3. Load standards artifacts for stack
4. Compare with existing files
5. Apply missing/outdated artifacts
6. Generate apply report

**Outputs:**

- List of files created/updated
- Apply report JSON

**Idempotency:** Running twice produces identical results.

#### 3.3 Doctor Command (`src/commands/doctor.ts`)

**Usage:**

```bash
repo-standards doctor <verify-result.json>
repo-standards doctor --stdin        # Read from stdin
```

**Algorithm:**

1. Parse `VerifyResult` from input
2. Analyze each finding
3. Classify by `remediation_class`
4. Generate remediation strategies
5. Build routing analysis

**Outputs:**

- Grouped findings by remediation approach
- Actionable remediation hints
- Routing recommendations for conductor

#### 3.4 Migrate Command (`src/commands/migrate.ts`)

**Usage:**

```bash
repo-standards migrate --from 6.0.0 --to 7.0.0
repo-standards migrate --from 6.0.0 --to 7.0.0 --path .
repo-standards migrate --list-versions
```

**Algorithm:**

1. Load migration rules between versions
2. Identify breaking changes
3. Generate migration plan
4. List required actions

**Outputs:**

- Migration plan JSON
- Breaking change warnings
- Step-by-step migration guide

## Dependency Analysis

### New Runtime Dependencies

| Dependency                   | Purpose               | Justification                      |
| ---------------------------- | --------------------- | ---------------------------------- |
| `uuid`                       | Session ID generation | Required for UUID v4               |
| `@iarna/toml`                | TOML parsing          | Required for `.odd/standards.toml` |
| `fast-json-stable-stringify` | Deterministic JSON    | Already in devDeps                 |

### Dependency Decision

Move `fast-json-stable-stringify` from devDependencies to dependencies (required for deterministic input hashing).

Add minimal new dependencies:

- `uuid` — lightweight, well-maintained
- `@iarna/toml` — lightweight TOML parser
